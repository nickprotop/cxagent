// Sessions

What a session looks like

Every capture is from a real session, in several of the built-in themes. Nothing is staged, and the mistakes are still in the pictures.

cxagent — session explorer

A session, end to end

Two workers explored a GPU monitoring tool and reported back. The agent wrote the summary you are reading from what they found, not from the files — and the panel on the right carries what that cost while it happened: 1.2M tokens across workers. The system prompt is built the same way every turn, so what the model has already read stays read.

An agent in its own tab

Sub-agents run in the background, listed in the tasks panel. Open one and it has a tab of its own: its brief, each step's thinking and tool calls, and its answer as it is written — with Stop, and a composer that talks to it rather than to the session.

Agents in the background

A spawn returns at once and the parent carries on; each report arrives as a message when it is done. F7 turns the right-hand column into the tasks panel — what is running first, then what has finished — and Enter on one opens it in a tab.

Ctrl+B moves what a turn is waiting on to the background mid-run, and x stops a running agent.

A file open beside the conversation

/open puts a file in a tab, with its language's highlighter and a save that keeps the BOM and line endings. Here the agent wrote the file while it had unsaved edits: the edits are kept, and the bar says so, with Reload and See theirs.

A save tells the model you edited the file, so it does not go on editing from a read you have since changed.

A terminal, for what a tool cannot do

A captured stream has nothing to type into, so a sudo password or a git rebase -i is where an agent stops and hands the job back. /shell opens a real PTY in a tab of its own, beside the conversation — the colours are the giveaway, since ls emits them only when it believes it is talking to a terminal.

Afterwards the agent is told what happened, queued rather than delivered into a turn of its own — so it does not start talking while you are still reading.

A question on the side

/btw asks about what the agent knows without adding to what it remembers. The aside starts from the conversation as the agent last sent it and answers in its own block while the main turn carries on — the calls above and below it are the agent, still reading.

It can read and nothing else, under the session's own permissions; a read the agent would be asked about is asked about here too.

A screenshot in the conversation

Ctrl+V pastes an image from the clipboard as a token, and dropping a file on the terminal does the same. The model is sent the picture, shrunk to 1568 pixels on its long edge; here Claude Haiku reads it. Ctrl+G, or a click on the message's image button, opens it in a window of its own.

Kitty draws the pixels, any other terminal draws half-blocks, and the system viewer is a button away. A model that cannot see images is sent a note naming each one, so the conversation goes on.

Trusting a folder

The first question of the first session. Reads and writes inside this folder stop asking; anything that writes elsewhere, and every shell command, still stops.

// Features

What is in it

The workbench first, then what keeps it in your hands: the prompts that stop it, a prompt that does not move under a running conversation, and the real bytes on disk.

01

Several agents, one window

/sessions new opens another conversation in its own tab, on any folder you like, with its own history, model, plugins and permissions — a question asked in one never answers for another. F6 moves to the tab strip and ← → change tabs; a tab waiting on a permission prompt says so.

02

Sub-agents in the background

A spawn returns at once and the parent carries on; each report arrives as a message when it is done. F7 lists what is running, Enter opens one in a tab with a composer that talks to it, and Ctrl+B moves what a turn is waiting on to the background. Each worker has its own context, and an agent type can run on its own model. Agent types →

03

A file opens beside the conversation

/open puts a file in a tab — line numbers, its language's highlighter, and a save that keeps the bytes you did not edit. It tells the model afterwards; and when the agent writes a file you have unsaved edits in, yours are kept, with Reload and See theirs.

04

A real terminal when one is needed

A captured stream has nothing to type into, so a password prompt or an interactive rebase is where most agents hand the job back. /shell opens a PTY in a tab beside the conversation; what happened there reaches the model afterwards, queued rather than delivered into a turn of its own.

05

Bring your own model

Ollama, llama.cpp, any OpenAI-compatible endpoint, or Anthropic — per tab, and switchable mid-conversation. Paste or drop a screenshot and a model that can see is sent the picture. There is no cxagent account and no cxagent server: it talks to the endpoint you configure, the MCP servers you add, and whatever a tool call reaches for.

06

It asks before it reaches out

In a folder you trust, reads and commands that only read stop asking, and writes inside it go through without asking in accept-edits mode. Commands that can write, and anything outside the folder, still stop. /btw asks a side question under the same rules, without interrupting the turn.

07

A second model can answer the prompts

Name a classifier in your config and /mode edits auto reviews each write that would otherwise stop you. It fails closed — a timeout, an error or anything it cannot parse means ask, never allow.

08

A plugin is a decision, not an install

Install one from the catalog with F2. Before any of it runs, cxagent reads the sidecar file beside it, shows you a hash of everything it would load, and asks — every time that hash changes.

09

The prompt does not move

Built the same way every turn, from facts sorted into a fixed order — so an MCP server connecting at turn 82, or a skill the filesystem happened to list differently, does not rewrite what the model has already read.

10

A conversation you can come back to

Every session in a folder is recorded and listed, with the goal that started it — /sessions resume 2, or by id from the command line. /compress summarises a full one in place, and F12 exports any of them as markdown, with each sub-agent's work where it happened.

11

Some questions do not need the model

/diff reads the working tree, /stats reads the ledger, /sessions reads what is recorded. They answer from git and from disk, spending nothing and adding nothing to what the model has to read.

12

MCP, skills and your own commands

Tools from any MCP server sit beside the built-in ones. A skill is a SKILL.md the model loads when a task needs it, and a markdown file becomes a command like /review 42. Your Claude Code commands and skills work as they are.

13

Thinking you can see, and set

Each step's thinking is its own block, folded until you open it — from a local llama.cpp model or from Claude. /think and F10 choose how hard it thinks, from the levels the model itself says it accepts.

14

One goal, or a script full of them

cxagent -p runs a goal with no window and prints the answer, as text, JSON or a stream of events. -c carries a script's next step on in the same conversation, which then opens in the TUI like any other. Anything that would have asked is refused and listed in the result.

15

Work that starts without you typing

A plugin can declare that it may start work in its own session, and the load prompt says so before you approve it. Unwiring it stops the turn it started — and leaves the one you started alone.

// Warning

Read this before you run it

It edits your files. Inside the working folder it writes without asking — that is the point of it, and it is why you should run it in a git repository with your work committed. git diff is the review step; there is no undo inside cxagent.

It runs shell commands, and it spends your money. Every turn is a request to whichever provider you configured, and a sub-agent is a whole second run of turns. If you point cxagent at a paid API, you are paying for what it does, including work that turns out to be wrong.
