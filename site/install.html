Install

A self-contained binary, a .NET tool, or a build from source.

Linux and macOS

curl -fsSL https://raw.githubusercontent.com/nickprotop/cxagent/master/install.sh | bash
cxagent

The script picks the binary matching your platform and puts it in ~/.local/bin as cxagent, with cxagent-uninstall.sh beside it and a plugin-host folder that native plugins run in. No .NET is required — the binary carries its own runtime — though on Linux it loads the system's ICU library (libicu) at start, which most distributions already have. If ~/.local/bin is not on your PATH, it adds an export line to ~/.zshrc, or to ~/.bashrc when there is no ~/.zshrc; with neither file it changes nothing, and you add the directory yourself. Open a new shell afterwards, or source the file it names.

It installs no plugins. The plugin manager (F2) fetches them, and nothing it fetches loads until you say so. See Plugins.

Reading the script first

Piping a script into a shell runs whatever it says. To read it before it runs:

curl -fsSLO https://raw.githubusercontent.com/nickprotop/cxagent/master/install.sh
less install.sh
bash install.sh

Windows

irm https://raw.githubusercontent.com/nickprotop/cxagent/master/install.ps1 | iex
cxagent

Run it in PowerShell. It puts cxagent.exe in %LOCALAPPDATA%\cxagent, with cxagent-uninstall.ps1 and the plugin-host folder beside it, and adds that directory to your user PATH — open a new terminal before typing cxagent. No .NET is required, and, as on Linux and macOS, no plugins are installed.

To read the script before it runs:

irm https://raw.githubusercontent.com/nickprotop/cxagent/master/install.ps1 -OutFile install.ps1
notepad install.ps1
powershell -ExecutionPolicy Bypass -File .\install.ps1

As a .NET tool

Requires the .NET 10 SDK: dotnet tool install is an SDK command, and a machine with only the runtime does not have it. Unlike the binaries this one is framework-dependent — it uses the .NET you already have rather than carrying its own.

dotnet tool install -g cxagent
cxagent

From source

Requires the .NET 10 SDK. On Linux, build-and-install.sh publishes a self-contained binary and copies it to ~/.local/bin/cxagent, adding that directory to your PATH the way the install script does:

git clone https://github.com/nickprotop/cxagent.git
cd cxagent
./build-and-install.sh

It runs on Linux and macOS, x64 or ARM, and builds for the machine it runs on. On Windows, publish it yourself and put the result on your PATH, in PowerShell:

git clone https://github.com/nickprotop/cxagent.git
cd cxagent
dotnet publish cxagent/cxagent.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -o publish\win-x64
.\publish\win-x64\cxagent.exe

Use win-arm64 on ARM. A source build leaves out the plugin host the install scripts add, so native plugins do not load from it; managed ones do.

The binaries

Every release publishes six. If you would rather not pipe a script into a shell, download the one for your platform from the latest release, make it executable, and put it somewhere on your PATH:

chmod +x cxagent-linux-x64
mv cxagent-linux-x64 ~/.local/bin/cxagent

A binary on its own runs every managed plugin. Native (.so/.dylib) plugins also need the cxagent-plugin-host-<platform>.zip from the same release, unpacked into a plugin-host folder beside the binary — the install scripts do this for you — and a .NET 10 runtime, which that host runs on.

Verifying a download

Each release carries a SHA256SUMS asset, computed from the artifacts the release actually built. Fetch it from the same release as the binary and check the file you downloaded against it:

curl -fsSLO https://github.com/nickprotop/cxagent/releases/latest/download/cxagent-linux-x64
curl -fsSLO https://github.com/nickprotop/cxagent/releases/latest/download/SHA256SUMS
sha256sum --check --ignore-missing SHA256SUMS

On macOS, shasum -a 256 takes the same --check. On Windows:

Get-FileHash .\cxagent-win-x64.exe -Algorithm SHA256

and compare the value against the matching line in SHA256SUMS.

This check proves the file you downloaded is the file that release published — it catches a corrupted or truncated download. It does not prove who built it.

macOS: Gatekeeper

The binaries are not notarised by Apple. A file fetched with curl, which is what the install script does, carries no quarantine flag and runs as it is. One downloaded with a browser is flagged, and macOS refuses to open it from an unidentified developer. Clear the flag on that one file:

xattr -d com.apple.quarantine ./cxagent-osx-arm64

or try to run it once, then allow it under System Settings → Privacy & Security with Open Anyway. Check the download against SHA256SUMS first: either step tells macOS to stop asking about that file.

First run

You do not need to write any configuration to start. With no config file, or none that names a working provider, the configuration dialog opens on a card for each place your model can run — Anthropic, OpenRouter, OpenAI, Ollama, llama.cpp or any OpenAI-compatible endpoint — lists the models that endpoint serves, and writes the file for you. After that, F8 opens the same dialog.

The file lands in ~/.config/cxagent/config.json on Linux and macOS ($XDG_CONFIG_HOME/cxagent when that is set), and in %APPDATA%\cxagent\config.json on Windows. The same directory holds your session history, logs and plugins. --config-dir points one run at another directory. Every configuration key →

Uninstalling

Installed with the script, on Linux or macOS — the uninstaller sits beside the binary:

cxagent-uninstall.sh
# or, if that is gone:
curl -fsSL https://raw.githubusercontent.com/nickprotop/cxagent/master/uninstall.sh | bash

It removes ~/.local/bin/cxagent, the uninstaller and the plugin-host folder, and the PATH line the installer added — that line alone, leaving any other line that names ~/.local/bin. The uninstaller that came with 0.10.2 or earlier cannot remove that line on macOS; run the one from master above instead, or delete it from ~/.zshrc yourself. A Linux build from source landed in the same place, so the same command removes it.

Installed with the script, on Windows, in PowerShell:

irm https://raw.githubusercontent.com/nickprotop/cxagent/master/uninstall.ps1 | iex

It removes cxagent.exe, the uninstaller and the plugin-host folder from %LOCALAPPDATA%\cxagent, the folder itself once empty, and the entry it added to your user PATH.

The .NET tool:

dotnet tool uninstall -g cxagent

A binary you downloaded, or published from source, yourself: delete the file, and the plugin-host folder if you made one.

None of these touches your configuration or session history — it holds your API keys and your past sessions, and an uninstall should not lose either. Delete the directory to remove them too, along with any plugins installed into it:
